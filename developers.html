Three steps to your first request

  1. Create a workspace credential

    Settings → Developers → New API key. Keys are scoped to a single workspace and shown once. Rotate at any time; the previous key stays valid for 24 hours so a deploy can overlap.

  2. Send it as a bearer token

    Pass the key in Authorization and name the workspace in ADOS-Workspace. A mismatch is rejected rather than silently scoped down.

  3. Handle rate limits

    Exceeding the limit returns 429 with Retry-After. Respect it; retrying immediately extends the window rather than shortening it.

first request
# List everything waiting on a decision
curl https://api.ados.ai/v1/drafts \
  -H "Authorization: Bearer $ADOS_API_KEY" \
  -H "ADOS-Workspace: ws_8f21c" \
  -G -d "status=awaiting_approval"

Base URL https://api.ados.ai. HTTPS only — plaintext is refused rather than redirected.

Authority

How ADOS holds authority.

Authorization Code with PKCE

ADOS never requests, receives or stores passwords for a connected service.

Incremental scopes

Narrowest permissions, requested at the moment the feature is connected.

Rotating refresh tokens

Replay detection; a reused token invalidates the chain and alerts the workspace owner.

Revocable from either side

Disconnect in ADOS or revoke at the provider. You never need our cooperation to cut off access.
